# Spike 03: MCP tool-surface trust (`@air/dsh-mcp-trust`)

Status: research spike, 2026-09-29. It implements the design in [research/notes/04-mcp-security.md §3](../../../research/notes/04-mcp-security.md) and [02-air-extraction.md §2.1](../../../research/notes/02-air-extraction.md). It answers nine open questions with facts checked in this checkout (dsh 0.2.0-rc.1, `@modelcontextprotocol/client` 2.0.0). Line numbers refer to the current files.

## 0. Findings that change the research design

1. **An out-of-tree plugin cannot write an `ignorable: true` session event today.** `Session.append(type, data, ...opts)` (`packages/core/session/src/index.ts` L722-751) builds the event from `type`, `seq`, `time`, `data` and surface metadata only. It has no `ignorable` parameter. Only seeded events (`Session.create` with a seed, L200-240) can carry the marker. `KNOWN_SESSION_EVENT_TYPES` is generated by scanning `packages/*/*/src` only (`scripts/persistence-catalog-source.ts` L142, L220, L266), so `air/` types are never "known". `validateStoredEvents` (`packages/session/session-persistence/src/storage-contract.ts` L74-80) refuses any unknown event without `ignorable: true`. An AIR `session.append('mcp/surface', …)` would therefore make the session **unloadable even by AIR's own build**. §3 gives two options. The recommendation is a sidecar audit log with zero delta, with a 12-line `append` option kept as a candidate.
2. **Tool and system-prompt assembly happens before `agent/pre-step`** (`packages/core/agent-loop/src/agent.ts` L267-285: `systemPrompt.assemble` runs, then the `agent/pre-step` waterfall). An approval granted at `turn/start` or pre-step affects the **next step** of that turn, not the first request.
3. **Duplicate JSON keys cannot be detected at this layer.** The MCP SDK parses JSON-RPC with `JSON.parse` (last key wins) before `listTools` returns. Scenario 20 therefore covers lone surrogates and duplicate raw tool names only.
4. **A Cordis waterfall is fail-open at startup and during HMR.** A service injected at the row level is fail-closed (§1.1). The hook should be an optional service that mcp-client reads, and AIR's mcp-client rows should declare `inject: [mcpToolReview]`.
5. **`ttlMs` is not surfaced by the SDK's types, but it is present at runtime.** `syncTools` already calls `listTools(undefined, { cacheMode: 'refresh' })`. The client preserves page-1 `ttlMs` on the aggregated result (`_listAllPages`/`_freshness` in the client `dist/index.mjs`). The SDK never re-lists on expiry, so re-verification timers are the trust plugin's job (§9).

## 1. In-tree hook: optional `mcpToolReview` service read in `syncTools`

### 1.1 Why a service rather than a waterfall event

| Concern | Waterfall `mcp/tools/review` | Optional service `ctx.get('mcpToolReview')` + row `inject` |
|---|---|---|
| Startup ordering | No activation dependency: the first generation can sync before the listener exists, so tools register **unreviewed** | Loader merges row `inject` with plugin inject (`vendor/loader/src/index.ts` L134, `EntryOptions.inject` in `vendor/loader/src/config/entry.ts` L22); the row waits for the service |
| HMR of the trust plugin | Listener gone for a window, so a `list_changed` in that window registers unreviewed tools | Service disposal disposes the dependent mcp-client fiber (tools unregistered), and it restarts and re-reviews when the service returns |
| Digest integrity | Earlier listeners may rewrite the list before the verifier sees it | One authority receives the list exactly as fetched |
| Missing reviewer | Silent pass | The row stays pending, and the startup report names the missing service ("1 entry did not activate", as in `apps/cli/tests/profiles/headless/tests/mcp-pagination.expected.e2e.ts`) |

Rows without the `inject` still read the service opportunistically. When no service exists, behavior is exactly upstream behavior, so no upstream test changes meaning.

### 1.5 Fetch failure versus drift

| Event | Where | Effect |
|---|---|---|
| `listTools` throws, pagination cap, duplicate raw name | phase 1, before review | Rejects. Previous generation and instructions stay registered (upstream contract, "we don't know") |
| Reviewer returns a subset (withhold) | phase 2 | Previous generation disposed; only accepted tools register |
| Reviewer returns `{ tools: [], instructions: '' }` (reject-generation) | phase 2 | Zero tools, prompt section withdrawn; the trust plugin records `Quarantined` |
| Reviewer throws (lockfile unreadable, bug) | `reviewGeneration` catch | Treated as reject-generation (fail-closed), **not** as fetch failure |
| Registry conflict | phase 2 (unchanged) | Rollback to zero tools; instructions are already published. Acceptable, because tools and prompt are both server-owned and the conflict is logged |

### 1.6 HMR and disposal

- **Trust plugin reload:** the service is disposed, so every mcp-client row injecting it is disposed (the connection closes and tools are unregistered). The row restarts when the service returns. The cost is a server restart per trust reload, which is acceptable.
- **mcp-client reload:** stale `resync` closures from the old supervisor are no-ops (`isCurrent`/`disposed`). The trust plugin must key its state by `serverName` and tolerate a new generation replacing the old one.
- **Guards, the pre-step listener and file watchers** belong to the trust plugin's effects (`ctx.tools.guard` returns an effect disposer, `packages/core/tools/src/index.ts` L1127-1142).

## 4. Lockfile storage

- **Location:** one explicit Config field `lockfile` (no default, following the no-hardcoded-tunables rule), set in the shared AIR servers bundle to `!!js dshHomePath('air', 'mcp-lock.json')`. A per-profile path (`ctx.profileContext.dir`, `packages/boot/app-boot/src/profile-context.ts` L15-30) would split pins between the `air` and `air-mcp` profiles (§5). A per-workspace `.dsh/mcp-lock.json` does not fit, because mcp-client connections are process- or Agent-scoped (`scopeOf`, `packages/mcp/mcp-client/src/index.ts` L162-176), not workspace-scoped, and the Web host serves many workspaces. Users who want reviewable team pins point `lockfile` at a path in a repository.
- **Write:** `@deepseek-ai/dsh-atomic-write` (public, zero dependencies): `withFileLock(path, op, { waitMs })` around read, modify and `writeFileAtomic(path, JSON.stringify(doc, null, 2) + '\n', { mode: 0o600, dirMode: 0o700 })` (`packages/util/atomic-write/src/index.ts` L49-93, L199-260). The lock requires the parent directory, so `mkdir` it first. Readers stay lock-free because commit is a rename. Declare it as a peer and dev dependency, like other dsh packages.
- **Why not `dsh-storage-json`:** it stores domain units under `storages/` with version stamps and a backend chosen by config. That is right for app data, but a pin file must be a named, diffable, human-reviewed file.
- **Read:** validate with Schemastery at load (durable/file boundary). An unknown `version`, a parse error or an unreadable file makes every review return reject-generation, logged loudly. Watch the parent directory with `fs.watch` (debounced, re-read, then `resync()` every server and recompute guard state), so a CLI `revoke` takes effect in a running Web process.
- **Format** (research note 04 §3.2 with fixed names):

```json
{
  "version": 1,
  "canonicalization": "RFC8785-JCS/SHA-256",
  "servers": {
    "browser": {
      "surfaceDigest": "sha256:<hex>",
      "instructions": { "digest": "sha256:<hex>", "text": "…" },
      "tools": {
        "browser_navigate": {
          "digest": "sha256:<hex>",
          "fields": { "description": "sha256:<hex>", "inputSchema": "sha256:<hex>" },
          "definition": { "name": "browser_navigate", "description": "…", "inputSchema": {} },
          "approvedAt": "2026-09-29T10:00:00Z",
          "approvedBy": "cli"
        }
      }
    }
  }
}
```

`approvedBy` is one of `"cli" | "command" | "tofu"`. Absent fields are omitted, not written as `null`, both in `fields` and in the digest input.

## 5. CLI without violating "Application launch"

Options checked:

| Option | Verdict |
|---|---|
| Package bin (`air-mcp pin …`) | Forbidden by root AGENTS.md |
| New launcher subcommand `dsh mcp …` | Edits `apps/cli/src/args.ts` (a large delta on a hot file) |
| `--patch` overlay on the `air` profile | Works, but must disable `web-startup` and leaves Web rows pending, and the `web-app` startup parser rejects `pin` if left on |
| Model-invisible `/mcp-trust` command (`ctx.commands.register`, `packages/interaction/commands/src/index.ts` L61-78, L285) | Good in-session UX, but UI-only (no adapter in headless or ACP) and unusable for CI `verify` |
| **Dedicated `air-mcp` profile with a `dsh-cmdline` startup provider** | **Recommended.** Same pattern as `@deepseek-ai/dsh-headless/startup`; covers pin, diff, verify and revoke with exit codes |

Composition. `air` = web template + `@air/dsh-air-bundle` + `@air/dsh-air-mcp-servers`. `air-mcp` = `@deepseek-ai/dsh-base` + `@air/dsh-air-mcp-servers` + `@air/dsh-mcp-trust-cli`. The shared servers bundle holds the trust row and every mcp-client row with `inject: [mcpToolReview]`, so both profiles connect to identical configs and read one lockfile. The base-layer disables currently in `@air/dsh-air-bundle` (`session-log-deepseek`, `deepseek-account`, `llm-deepseek-account`, `web-search-deepseek`) should move to that shared bundle or to an `@air/dsh-air-base` bundle, so that `air-mcp` does not contact vendor services. The Web-only disables stay in the AIR bundle to avoid unmatched patch targets.

Invocation: `pnpm dsh --profile air-mcp pin browser`, `… diff browser`, `… verify --all` (non-zero on drift), `… revoke browser --tool browser_evaluate`. The launcher hands `['pin', 'browser']` to the tree (`apps/cli/src/args.ts` header comment).

export type TrustCliInvocation =
  | { kind: 'pin'; server: string; tools?: string[]; yes: boolean }
  | { kind: 'diff'; server: string }
  | { kind: 'verify'; all: boolean; server?: string }
  | { kind: 'revoke'; server: string; tools?: string[] }

export function apply(ctx: Context): void {
  let invocation: TrustCliInvocation | undefined
  const program = new Command().name('dsh --profile air-mcp').helpOption('-h, --help', 'show this help')
  program.command('pin <server>').option('--tool <name...>').option('--yes')
    .action((server: string, o: { tool?: string[]; yes?: boolean }) => { invocation = { kind: 'pin', server, tools: o.tool, yes: o.yes === true } })
  program.command('diff <server>').action((server: string) => { invocation = { kind: 'diff', server } })
  program.command('verify [server]').option('--all')
    .action((server: string | undefined, o: { all?: boolean }) => { invocation = { kind: 'verify', server, all: o.all === true } })
  program.command('revoke <server>').option('--tool <name...>')
    .action((server: string, o: { tool?: string[] }) => { invocation = { kind: 'revoke', server, tools: o.tool } })
  parseCmdline(ctx, program)                         // help/usage errors exit through ctx.appExit
  if (invocation === undefined) return
  const run = invocation
  ctx.effect(() => ctx.appReady!.onReady(() => {     // after every mcp-client row finished its initial sync
    void runTrustCli(ctx.mcpTrust, run).then(code => ctx.appExit!(code), () => ctx.appExit!(2))
  }), 'air-mcp-trust-cli.run')

```

`parseCmdline(ctx: Context, program: Command): void` runs synchronous actions only (`packages/boot/cmdline/src/index.ts` L147-186). `appReady.onReady(listener): () => void` fires after the Loader tree settles, and the launcher always provides it (`apps/cli/src/profile-boot.ts` L307-311). `pin` without `--yes` on a non-TTY stdin refuses and prints the diff. With a TTY it prompts for confirmation. `mcpTrust` is the trust plugin's second service. It keeps the **last observed** surface per server (including withheld or rejected ones), so `pin` writes what the process actually fetched.

The `/mcp-trust diff|pin|revoke <server>` command in the trust package is optional follow-up. A slash command is an explicit user action, so it may write the lockfile (`approvedBy: "command"`) and call `resync()`. It runs outside turns, so it must not call `approval.request()`.

        signal: payload.signal,
      })
      if (outcome === 'allowed-once') { state.acceptOnce(pending); pending.resync() }   // process memory only, never the lockfile
    }
    audit.recordTurn(payload.agent.session, payload.turn)
  }
  return next()                                               // must delegate (waterfall rule)
})
```

Known limitation: the accepted tools appear from the next step of the turn, because assembly already ran (§0.2). Headless `policy: never` stays fail-closed.

Recommendation: **`canonicalize@5.1.0` pinned exactly**, behind a roughly 25-line local wrapper that enforces I-JSON before hashing: plain objects and arrays only, finite numbers, and `String.prototype.isWellFormed()` on every string and key (lone surrogate leads to reject-generation). The wrapper is needed with any library, and hand-rolling JCS number serialization is where implementations diverge. Apache-2.0 is compatible, but keep its license text in distributions. Cross-language vectors: Python `rfc8785` 0.1.4 (Trail of Bits, Apache-2.0, Python ≥3.8, last release 2024-09-27) generates a committed golden file once. CI compares TypeScript output only and does not need Python.

Digest inputs: `toolDigest = sha256(JCS({ name, title?, description?, inputSchema, outputSchema?, annotations?, execution? }))`. Per-field digests use the same function. `surfaceDigest = sha256(JCS({ instructions: digest | null, tools: { [rawName]: toolDigest } }))`. Instructions are hashed as the raw server text (trimEnd), without dsh attribution, and without Unicode normalization.

## 9. MCP SDK version and `ttlMs`

- `@modelcontextprotocol/client` **2.0.0** (exact) in `packages/mcp/mcp-client/package.json`; tests use `@modelcontextprotocol/server` 2.0.0 and `@modelcontextprotocol/node` 2.0.0. The client negotiates the era (`versionNegotiation: { mode: 'auto' }`, `connection.ts` L258-271).
- `ListToolsResult` = `StripWireOnly<Infer<ListToolsResultSchema>>`; only `resultType` is stripped. `ttlMs` is not a declared member, but the loose schema keeps it, and `_listAllPages` preserves page-1 `ttlMs`/`cacheScope`, which `_freshness` reads from the runtime body. `CacheableRequestOptions.cacheMode: 'use' | 'refresh' | 'bypass'`; server TTLs are capped at 24 h (`MAX_CACHE_TTL_MS`). The SDK does not schedule re-listing on expiry.
- The trust plugin arms `setTimeout(request.resync, clamp(ttlMs, minReverifyMs, maxReverifyMs)).unref()` per server after each review. Both bounds are Config fields. `ttlMs: 0` or an absent value means no timer; `list_changed` and reconnects still re-verify.
- SEP-2243 exclusion (`_excludeInvalidXMcpHeaderTools`) removes some tools before the harness sees them. Such a tool reviews as "removed" (accepted and logged).

## 14. Risks

- **Fork carry cost:** `syncTools` and `connectGeneration` are the most change-prone mcp-client code. Keep the hook confined to `review.ts` plus two insertion points, with tests in a separate file.
- **Era-dependent digests:** the 2026 codec enforces deleted fields (`execution.taskSupport`), so the same server can present different `execution` under 2025 and 2026 negotiation. An SDK upgrade or server upgrade that switches era looks like drift. Mitigation: record `protocolEra` in the lock entry and report era changes distinctly in `diff`.
- **SDK schema generation churn** (AIR's `mcp` 2.1.1 to 2.2.0 hold): server SDK bumps can change generated schemas. The diff UI must show field-level changes to keep re-pinning cheap.
- **Unreviewed rows:** a user-profile mcp-client row without `inject` bypasses review at registration. `denyUnreviewedMcpTools` blocks its calls but not its descriptions. The bundle patch test covers AIR-owned rows only.
- **Agent-scoped servers** reuse a `serverName` in several Agents (`activeServerNames` per scope). One lock entry covers all of them. Divergent per-Agent server configs would collide on one pin. Reject that configuration in `enforce` mode, or key by the scope label later.
- **Instruction timing change:** instructions now publish at the swap rather than after the attempt settles. A generation that closes right after its first sync leaves published instructions next to its registered tools, which matches existing tool behavior. Verify against `reconnect.spec.ts`.
- **Consent fatigue and cross-agent prompts:** cap prompts per server per process, dedupe concurrent Agents, and never prompt from subagents without a UI answerer (they receive `unavailable`).
- **Watcher portability:** `fs.watch` on network filesystems and WSL. Fall back to re-reading on every review, which already happens on `list_changed` and TTL.
- **`canonicalize` supply chain:** pin exactly and review diffs on bump. The local I-JSON wrapper keeps the security-relevant rejects in owned code.
- **Launch pinning** (research note 04 §3.8) is out of scope for this spike. The `launch` block can be added to the lock entry later without changing the verdict interface.
