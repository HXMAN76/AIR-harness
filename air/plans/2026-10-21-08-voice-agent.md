# AIR voice agent (Phase 1 glimpse) — design

Date: 2026-10-21. Status: design, approved for a spike on 2026-10-21; this document is the spec for review. Upstream base: `dsh-v0.2.1-rc.2`.

## Goal

A hands-free voice companion for native Windows that a person starts with a wake phrase, speaks a request to, and hears the answer from. The agent behind it can run PowerShell, browse and search the web, control desktop windows when a vision-capable cloud model is selected, and remember facts across sessions. It is shown at the Phase 1 review as a glimpse of Phase 2, through a short scripted scenario.

Success at the review:

1. "Hey AIR, open Notepad and write my todo list: buy milk, call Ravi." Notepad opens with the text; the reply is spoken.
2. "Hey AIR, search the weather in Chennai." A spoken summary from a web page.
3. "Hey AIR, remember that I like short answers." In a new session: "Hey AIR, how do I like answers?" The fact is recalled.
4. Switching the model route by voice or by the window toggle: local `qwen3-8b-32k` (default), cloud Claude Haiku 5.5 for conversation, Claude Sonnet 5.5 for screen control.

## Constraints

- Local first (`air/AGENTS.md`): the default route is local Ollama, and audio never leaves the machine. The cloud route is opt-in per session. The user enters `ANTHROPIC_API_KEY` in the voice home's `.env` or Settings; AIR code never reads or prints it.
- Out of tree: everything lives in `air/`. No upstream edits.
- No custom session event types. Memory audit data goes to files under the harness home.
- Native Windows first; Linux should work but is not a review target. macOS is out of scope.

## Spike results (2026-10-21)

| Risk | Result |
|---|---|
| Microphone capture without a new native dependency | Electron `getUserMedia` with an `AudioContext` at 16 kHz delivered mono Float32 frames to the main process. |
| Local speech-to-text | `sherpa-onnx-node` 1.13.8 (already an upstream dependency) with upstream's pinned SenseVoice int8 model: 4.1 s model load once, 0.26 s to decode 5 s of audio on the CPU. |
| Driving an agent from another process | Upstream's TypeScript SDK (`@deepseek-ai/dsh-sdk-client`, `DeepSeekHarness`) ran a turn on `qwen3-8b-32k` that called `pwsh` and returned the result (about 30 s per turn after the first boot, about 100 s for the first). |
| Windows sandbox | `pwsh` with `workspace-write` failed with `SetNamedSecurityInfoW failed (Win32 5): grantWrite(G:\AIR-harness)`. With the workspace under the user profile (`Documents`) it worked. The voice workspace therefore defaults to `Documents\AIR Voice`. |
| Speech output | Windows SAPI voices (Microsoft David, Zira) are available through `System.Speech`. |
| Not tested | The Anthropic route (needs the key), computer use through Cua Driver on Windows, and Playwright MCP. |

## Architecture

```
┌──────────── air/apps/voice (Electron) ─────────────┐
│ renderer: mic capture (16 kHz) · status window     │
│      │ PCM frames (IPC)                ▲ state     │
│ main ▼                                 │           │
│  listener ──► wake phrase? ──► command text        │
│  (child process: Silero VAD + SenseVoice)          │
│                     │                              │
│  agent bridge (SDK) ─► dsh runtime (profile sdk +  │
│                     │   air-voice patch)           │
│                     ▼                              │
│  speaker (child PowerShell, SAPI) ◄── reply text   │
└────────────────────────────────────────────────────┘
```

Units, each with one job and a small interface:

1. **Capture (renderer).** `getUserMedia` (echo cancellation and noise suppression on) into an `AudioWorklet` at 16 kHz; posts 100 ms Float32 frames to main. Shows a status window: idle, listening, thinking, speaking; the last transcript; the reply; the active route.
2. **Listener (`listener.ts`, runs in a Node child process).** Streams frames into Silero VAD; each finished speech segment is decoded by SenseVoice. Emits `{ text, startedAt, durationMs }`. No wake logic here.
3. **Wake matcher (`wake.ts`, pure).** Normalises a transcript (lower case, punctuation removed, common mis-hearings mapped: "hey air", "hey ai", "hi air", "hey er") and returns `{ wake: boolean, command: string }`. A wake phrase with no command opens an 8-second window in which the next segment is the command. Configurable phrase list. Unit-tested with a table of transcripts.
4. **Agent bridge (`agent.ts`).** Owns one `DeepSeekHarness` per route and one session per conversation. `ask(command)` returns the final response and the tool calls made. Routes: `local` = `ollama/qwen3-8b-32k`; `cloud` = `anthropic/claude-haiku-5-5`; `screen` = `anthropic/claude-sonnet-5-5` with the computer-use rows enabled. Voice commands "use cloud", "use local", "use screen mode", and "new conversation" are handled before the agent sees them.
5. **Speaker (`speaker.ts`).** A long-lived PowerShell child process that reads lines from stdin and speaks them with `System.Speech.Synthesis.SpeechSynthesizer`; `stop` cancels speech (barge-in: a wake phrase while speaking stops speech first). Markdown, code blocks, and URLs are stripped before speaking; replies longer than about 60 words are spoken as their first two sentences, with the full text in the window.
6. **Voice profile (`profile/voice.cordis.patch.yml`).** Applied on top of upstream's `sdk` profile:
   - the Ollama route (from `air/examples/ollama.profile.cordis.patch.yml`) and an `anthropic` route through `llm-pi-ai` with `apiKeyEnv: ANTHROPIC_API_KEY`;
   - a voice persona instruction: answer in one to three short spoken sentences, no Markdown, say what you did;
   - `tool-web` with fetch on; the Playwright MCP browser rows for search on a search engine's HTML page;
   - the computer-use rows (`computer-use-cua-driver-native`) only in the `screen` route patch;
   - the memory rows from item 7.
7. **Memory (plan 04, trimmed).** Execute [plan 04](2026-09-30-04-memory-core.md) without its embedding and vector tasks: Markdown notes with git history under `dshHomePath('air', 'memory')`, the SQLite FTS5 index, the four tools, and the pinned core. `shareWith` defaults to `['ollama']`; the voice profile sets it to `['ollama', 'anthropic']` only when the user turns on "share memory with cloud" in the window (off by default), and the window says which.

## Data flow of one request

1. Frames stream from the renderer to the listener continuously while the app runs (microphone indicator on).
2. A speech segment ends; SenseVoice returns text in about 0.3 s.
3. The wake matcher drops anything without the wake phrase. Audio and transcripts of dropped segments are not stored.
4. The command goes to the agent bridge; the window shows "thinking".
5. The runtime runs tools (PowerShell in the voice workspace with `workspace-write`, the browser, memory). The SDK has no approval surface, so the voice profile keeps upstream's sandbox and denies `danger-full-access` escalation; anything that needs it fails and is said aloud.
6. The final response is spoken; the window shows the full text and the tool calls.

## Error handling

- Ollama not reachable, model missing, or the cloud key absent: spoken message naming the cause and the fix; the window shows the same.
- Microphone denied or missing: the window says so and offers a retry; nothing is sent.
- A turn longer than 120 s: spoken "still working"; the user can say "cancel", which closes and restarts the runtime (the SDK has no mid-turn cancel).
- Listener or speaker child exits: restarted once; a second failure is shown in the window.

## Testing

- Unit (vitest): wake matcher table, speech text cleaner, route command parser, frame buffering, the speaker's line protocol (with a fake PowerShell), and agent bridge route selection (with a fake SDK).
- Integration (opt-in, local only): a WAV fixture through the real listener; one SDK turn on `qwen3-8b-32k`.
- Manual: the four review scenarios on Windows, recorded in `air/CHECKS.md` with times.

## Out of scope for Phase 1

A trained wake-word model (open-vocabulary keyword spotting is the Phase 2 option; `sherpa-onnx-node` already ships it), neural TTS (sherpa-onnx `OfflineTts` is the Phase 2 option), streaming partial replies, approvals by voice, auto-recall in memory, a packaged installer.
